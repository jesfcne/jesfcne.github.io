# probes — 일회성 수집 기록

정기 수집기와 달리, 노트 한 편을 쓰려고 한 번만 긁은 데이터가 있습니다.
그런 수집의 조건을 여기에 기록합니다.

수집기 코드는 나중에 바뀌고, 원본 API는 조용히 응답을 바꾸며, 받은 파일은
용량 때문에 저장소에 못 올리는 경우가 많습니다. 그래서 남는 건 "무엇을 언제
어떤 조건으로 받았는가" 하는 기록뿐입니다. 이게 없으면 반년 뒤에 같은 결과를
다시 만들 수 없습니다.

## 규칙

- 프로브 하나가 디렉터리 하나입니다. 이름은 `YYYY-MM-슬러그` 를 씁니다.
  예: `2026-09-airkorea-backfill/`
- 각 디렉터리에 `probe.md` 를 두고 아래 항목을 채웁니다.
- 받은 원본 데이터는 커밋하지 않습니다. 집계 결과만 `data/marts/` 로 보냅니다.
  용량 문제도 있지만, 원본을 그대로 재배포하면 출처 기관의 이용 조건과
  충돌할 수 있기 때문입니다.
- 프로브는 지우지 않습니다. 결과가 쓸모없었더라도 "해봤는데 안 되더라" 는
  기록 자체가 다음번에 같은 삽질을 막아 줍니다.

## `probe.md` 항목

| 항목 | 설명 |
| --- | --- |
| 목적 | 어떤 질문에 답하려고 받았는지 |
| 소스 | 기관과 엔드포인트 또는 다운로드 경로 |
| 요청 조건 | 기간, 지점, 항목, 페이지 크기 등 실제로 넘긴 파라미터 |
| 수집 시각 | 실행한 날짜와 시각 (타임존 포함) |
| 받은 양 | 행 수, 파일 크기 |
| 산출물 | 이 프로브가 만든 `data/marts/` 파일 이름 |
| 걸린 문제 | 결측, 응답 형식 변경, 속도 제한 등 다음 사람이 알아야 할 것 |

## 정기 수집기와의 경계

같은 프로브를 세 번쯤 반복하게 되면 그건 정기 수집기가 되어야 한다는 신호입니다.
수집기로 옮긴 뒤에는 `probe.md` 에 "이 프로브는 `<수집기 이름>` 으로 대체됨" 이라고
적고 그대로 둡니다.
